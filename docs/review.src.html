Short context, long memory

到阈值压一次，最划算

只看前沿模型、把用量算进去：EoCC（到阈值压一次）最好。SAC（每步一换）正确率不更高，论文也没给它花了多少 token。

按今天统一的标价，压缩不一定省钱：SWE-bench Verified 上 Opus 便宜约 10% 到 30%，GPT 反而贵约 10% 到 21%。论文标题里那 2.2 到 8.8 倍，是假设厂商按上下文长短定价的估算。所以对你来说，压缩换来的是正确率不掉、会话不糊涂，钱基本打平。

关于 DeepSeek Flash：论文没测它，它的跑分小克没核实。论文里有一组对照值得记：Step 3.7 Flash 和 Opus 4.5 不压缩时 SWE-bench 都是 70.0，压到 16K 上限时一个掉到 56.6，一个还有 68.8。跑分一样高，经不经得起压缩是两回事。所以给它派活，阈值放宽、任务切小。

小克上次说错一处：Qwen 3 Coder Next 从 53.0 掉到 3.6，原因不是它不会写总结。论文写的是它输出太啰嗦，两次压缩之间留不出空间干活。

表里「单次上下文」是一次调用里最大的那段对话。EoCC 取的是每格最好的那组设置：Opus 是 24K/18K 和 32K/24K，GPT 是 48K/36K。

要你定的一件事

仓库要不要公开？现在是私有的。

公开：和解剖、肥肥主义一样，别人能直接装来用；README 有中英两版，里面没有密钥、地址和账号。不公开：只有你看得到，以后随时能改成公开。

小克倾向公开：这套做法本身没有私事，论文撑着，放出去才有人用。顾虑是工具里有几句提示写着「问肥肥」，别人用时会看到你的名字。
